# План улучшения dmsh

Состояние на 2026-11-20, ветка `main`, последний коммит `da956e5`
(v0.5.2 + clickable TUI). План составлен по фактической проверке дерева,
а не по README: всё, что ниже, воспроизводится командами из раздела
«Как проверялось».

## 2. Что проверено (факты)

### 2.1. Тесты на Windows падают

`go test ./...` на Windows 11, Go 1.25:

| Тест | Поведение до фикса | Причина |
|------|--------------------|---------|
| `TestBackgroundOutputIsVisibleWhileRunning` | падал стабильно (3/3) | `tui.go:511`: `cmdTickMsg` возвращал `nil` вместо `waitForCmd`, очередь вывода переставала вычитываться |
| `TestDirMenuHandlesKeys` | падал периодически в полном прогоне | следствие первого: брошенная фоновая команда держала `cwd` внутри `t.TempDir`, и Windows не мог удалить каталог |

Первый — не только тест, а реальный дефект: фоновая команда, которая
молчит больше секунды, замирает в статусе `running`, её вывод и
`cmdDoneMsg` остаются в канале навсегда. Оба исправлены в S1 (см. раздел 0).

### 2.2. CI проверяет только Linux

`.github/workflows/ci.yml`: один `ubuntu-latest`, `go test ./...` без
`-count=1` и без `-race`, плюс `golangci-lint`. Windows- и macOS-специфичные
ветки (`conpty`, `terminal_windows.go`, пути, локи файлов) не проверяются
вообще.

| `internal/cli` | 56.6 % | самый большой и самый рискованный пакет |
| `internal/config` | 45.7 % | загрузка/сохранение/валидация |
| `internal/model` | 44.0 % | загрузчик моделей |

### 2.4. Секреты на диске

- `config.go:402` пишет `config.json` с правами `0644`, хотя там лежат
  `remote_api_key` и `proxy_password`.
- `session.go:514` (history) и `session.go:582` (audit) тоже `0644`;
  в audit попадают полные команды, включая возможные токены.

### 2.5. Чего нет в CLI

- Нет shell completion (`dmsh completion ...`, `ValidArgsFunction`) —
  при десятках флагов и подкоманд это заметная потеря.
- Нет машиночитаемого вывода (`--json`) и стабильного контракта кодов
  возврата: `run`/`ask` неудобно использовать в скриптах и CI.
- У моделей нет `remove` / `verify` / `prune`, загрузка без контрольной
  суммы и без докачки (`internal/model/downloader.go`).
- Политика не разбирает вложенные оболочки: `bash -c "rm -rf /"`,
  `cmd /c del /s /q C:\...`, `powershell -Command "..."` проверяются как
  обычная строка, поэтому denylist обходится.
- `doc/roadmap.md` и `doc/plan.md` описывают MVP 2024 года и не отражают
  текущее состояние; `doc/implementation_plan*.md` — исторический артефакт.

### 2.6. Расхождение с AGENTS.md

Разрешено 2026-11-22 в пользу безопасного дефолта: `config.Default()`
ставит `DryRun: true`, флаг `--dry-run=false` и настройка `dry_run: false`
включают авто-исполнение low-risk команд. README, REPL-help и сообщение
dry-run приведены к этому решению; новые пользователи без конфига видят
одноразовое предупреждение с флагом совместимости, старые конфиги с
`dry_run: false` продолжают работать как раньше.

`config.go` — 638, `modelmenu.go` — 522, `openai.go` — 527. Это уже мешает

### P1 — безопасность

6. **Разбор вложенных оболочек в `policy.Evaluate`.**
   Нормализовать команду и рекурсивно проверять содержимое
   `sh|bash|zsh -c`, `cmd /c`, `powershell|pwsh -Command`, `eval`,
   `xargs sh -c`, here-string. Отдельный набор тестов-обходов:
   `bash -c 'rm -rf /'`, `powershell -Command "Remove-Item C:\ -Recurse"`,
   `cmd /c rd /s /q C:\`, `echo cm0gLXJmIC8= | base64 -d | sh`,
   `find / -delete`, `:(){ :|:& };:` в кавычках.
   Сейчас покрыты только прямые формы — это главный риск проекта.
7. **Права на файлы с секретами.**
   `config.json` — `0600` на Unix (и предупреждение, если файл уже
   `0644`); `history.jsonl` и `audit.jsonl` — `0600`. На Windows
   задокументировать, что защита — ACL профиля, и не обещать лишнего.
   Тест: после `Save()` режим файла `0600` на Unix.
8. **Редакция секретов в выводе.** — сделано 2026-11-22: `redactOutput`
   собирает литеральные секреты из конфига (ключ из env, ключ из файла,
   пользователя/пароль прокси и URL-кредиты) и применяет `redact.Text`
   в `printNotice`, text/TUI `/setup`, `/model` и ошибках загрузки;
   `remoteEndpoint` маскирует `user:pass@host` у источника, поэтому все
   вызывающие получают уже безопасную строку. Тесты:
   `TestSensitiveValuesNeverReachOutput`, `TestRedactOutputPatterns`.
9. **Песочница файловых инструментов.**
   `read_file`/`list_dir` сейчас принимают любой путь. Ввести политику:
   рабочая директория и её подкаталоги по умолчанию, `~/...` — по
   настройке, запрет `..`-выхода после `filepath.Clean`, отказ на
   устройства (`/dev`, `\\.\`, `CON`), лимит на симлинки. Ошибка должна
   объяснять, какой путь и почему отклонён.
10. **Целостность загрузки моделей.** — сделано 2026-11-22: SHA256 +
    sidecar, докачка по `Range`, `verify/remove/prune` в CLI и TUI, а также
    проверка свободного места до запроса (по каталогу модели) и по
    `Content-Length` перед записью (`freespace_unix.go` / `_windows.go` /
    `_other.go`). Тесты — `freespace_test.go`.
11. **Решение по `dry-run`.** — сделано (вариант б): безопасный дефолт
    `DryRun: true`, совместимость через `--dry-run=false` / `dry_run: false`,
    предупреждение при первом запуске без конфига. Зафиксировано в README,
    REPL-help, CHANGELOG и тестах `config.Default().DryRun`.

**Готово, когда:** корпус обходов (≥40 кейсов) зелёный, `config.json`
создаётся `0600`, ключ не утекает в вывод, файловые инструменты не
выходят за разрешённый корень.

## 5. KPI / definition of done

- 0 падающих тестов на Linux, Windows, macOS; `-race` зелёный.
- Покрытие: `cli` ≥ 65 %, `config` ≥ 70 %, `model` ≥ 60 %,
  `feedback` ≥ 80 % или пакет удалён; общий итог ≥ 65 %.
- Корпус обходов политики ≥ 40 кейсов, все blocked/confirmed как надо.
- В `config.json`/`history.jsonl`/`audit.jsonl` нет прав `0644` на Unix.
- Кадр TUI ≤ 16 мс на 4000 строках; простой ≤ 1 % CPU.

## 6. Риски

- **Ужесточение политики** может заблокировать легитимные команды
  (`bash -c "make ..."`). Решение: блокировать только при опасном
  содержимом, остальное — `medium` + подтверждение.
- **Разбиение `tui.go`** механическое, но конфликтует с любыми
  параллельными правками. Делать одним PR, без изменения логики,
  опираясь на существующие `tui_test.go`/`click_test.go`.
- **Windows CI** медленнее и капризнее (ConPTY). Держать pty-тесты
  за build-тегом и в отдельном job, чтобы не тормозить основной.
- **Смена дефолта `dry-run`** ломает привычку и скрипты. Если менять —
  только с предупреждением при первом запуске и флагом совместимости.
