# dmsh v0.6.0 — plan mode, project docs, plugins and sessions

This is the first release since v0.5.2 and it is a big one: dmsh can now plan
work in reviewable steps, search your project's documentation, call allowlisted
helper executables as tools, and keep several named conversation sessions. The
CLI speaks consistent JSON, the TUI got search/copy and a debug log, and every
release artifact is now signed and verified.

## Added

### Plan mode

`/plan <request>` and `dmsh plan <request>` turn a request into a checklist in
`todo`. Nothing runs until you review it: `/plan run` or `dmsh plan --run`
executes the open steps through the same policy, confirmation and audit path as
`run_command`. A plan is a proposal you can edit, not a hidden macro.

### Local documentation search

`dmsh doc <query> --dir <path>` and TUI `/doc` index Markdown guides into a
local SQLite index and return matching chunks with `file:line` references, so
every answer can be checked against the source. The index is rebuilt on open —
no stale chunks, no background server.

### Plugins as policy-gated tools

Allowlisted `dmsh-*` executables found in `PATH` appear to the model as
`plugin_*` tools. Arguments are split into argv without a shell, so quotes
group words and metacharacters stay literal. Plugins go through the same
risk policy, confirmation and audit log as shell commands.

### Named sessions

Sessions can be named and switched, and `dmsh session rename <old> <new>`
renames one — including the default session. Overwrite protection keeps an
existing name from being clobbered. Turning `resume_session` on is no longer a
prerequisite for persisting turns.

### Diagnostics and scripting

- `--debug` / `--debug-file` write redacted logs with request timings,
  provider details and tool calls.
- `/stats` gained request errors, tool steps, TTFT, request/stream timing and
  stream counters.
- `ask`, `run` and one-shot queries support `--json`; `version`, `config show`,
  `doctor`, `history` and `session` do too. Errors share one JSON envelope with
  a kind, hint and exit code.
- `dmsh doctor` reports config, models, provider, proxy and network state with
  actionable hints; secrets are redacted everywhere, including the TUI.
- Config files carry a `config_version`: legacy `proxy_url` is migrated on
  load, and a config from a newer version is rejected explicitly.

### Release integrity and install targets

Releases ship verified `SHA256SUMS`, an ASCII-armored GPG signature and a
CycloneDX SBOM; publishing fails if any of them is missing. `make build-stub-repro`
produces a deterministic stub binary. `make install`, `make install-user` and
`make install-stub` install the binary with its man pages. `make checksums` and
`make release-artifacts` no longer depend on `sha256sum` or a specific
PowerShell version.

## Changed

- TUI and session internals were split into smaller modules; no source or test
  file exceeds 600 lines.
- Dry-run remains the safe default. The refusal now explains how to opt out
  with `--dry-run=false`, and first runs get a one-time notice.
- Free-text feedback hints are English, matching the rest of the interface;
  Russian stderr input is still recognized.
- Go sources use LF line endings and `make fmt-check` guards gofmt cleanliness.

## Fixed

- Ctrl+W / Alt+Backspace really deletes the previous word; aliases expand
  before the prompt; the documented `dmsh repl` command starts the TUI again.
- `--session` help, TUI confirm keys, action-bar hit targets, command wrapping
  and background output handling were corrected.
- Staticcheck findings and platform-specific test isolation: config/session
  tests now isolate `HOME` too, so the suite passes on macOS.
- The Windows "This is a command line tool" splash from Cobra's mousetrap no
  longer appears when dmsh is launched from Explorer or a shortcut.
