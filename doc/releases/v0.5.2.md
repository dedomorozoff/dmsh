# dmsh v0.5.2 — paste everywhere, install from source

Two small things: the paste key now works in every field the TUI edits, and a
binary built from source can be installed without hand-copying it to `/usr/local`.

## Fixed

### `Ctrl+V` worked everywhere except where it mattered

`tea.PasteMsg` was accepted only in the idle and question states, so the fields
that nobody wants to type by hand had **no paste path at all**:

- the API key in the setup screen (`Ctrl+P` → *setup*),
- the proxy login and password in the settings screen (`Ctrl+P` → *settings*),
- the filter lines of the model menu (`Ctrl+O`) and the palette.

A `sk-...` key or a proxy password had to be entered character by character, and
the window looked broken while doing it.

Paste is now routed to whichever field is actually active — the same way a key
press is — and in terminal mode it is forwarded to the pty, so
`Ctrl+V`/`Ctrl+Shift+V` inside the embedded shell pastes as expected. Pasting
outside an editable field is still ignored rather than silently changing a
value: the pasted password stays masked in the list, and the tests pin that a
paste with no open field reaches neither the password nor the input line.

## Added

### `make install` for source builds

Installing from source ended at `make build` — from then on it was `sudo cp` by
hand. Only Arch had a path (`make dist-arch` through `makepkg -si`). Three new
targets, all installing the binary **and** the man pages:

| Target | Destination | sudo |
|--------|-------------|------|
| `make install` | `$(PREFIX)/bin/dmsh`, default `/usr/local` | only if the prefix is not writable |
| `make install-user` | `~/.local/bin/dmsh` | never |
| `make install-stub` | as `install`, but built without `llama.cpp` | only if the prefix is not writable |

- `sudo` is added only when the prefix cannot be written; the check walks up to
  the nearest existing directory, because `~/.local` may not exist yet and `-w`
  on a missing path is always false.
- `PREFIX=` moves the destination (`make install PREFIX=/opt/dmsh`), `DESTDIR=`
  stages the tree for packaging and never pulls in `sudo`.
- `install-stub` skips the CGO build: no `llama.cpp`, no local GGUF, remote
  providers (Ollama, Pollinations) only — but seconds instead of a 15-minute
  compile.
- On Windows the targets print a pointer to `install.ps1`, which stays the way
  in there.

Release binaries are unaffected by these targets — `release.yml` builds with
`go build` directly — so installing from the `.deb`, `.rpm` or the tarballs is
still the shortest route for a packaged system.
