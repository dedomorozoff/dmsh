# dmsh v0.5.1 — Ollama, proxy, setup screen, live model catalog

A second remote provider, one screen that changes how dmsh connects, and a
TUI with a real command palette and an embedded terminal.

## What's new

### Providers: now with Ollama

| Provider | Behaviour |
|----------|-----------|
| `auto` (default) | local GGUF if one is found, otherwise Pollinations |
| `local` | local GGUF only; fails with a hint if none is present |
| `ollama` | a local [Ollama](https://ollama.ai) server over its OpenAI-compatible `/v1` endpoint; no API key |
| `pollinations` | Pollinations API; needs an API key, local models are ignored |

```bash
dmsh --provider ollama --remote-model qwen3:8b "list big files"
dmsh config set provider ollama
```

- Ollama answers on `http://127.0.0.1:11434/v1`, so nothing leaves the
  machine and no key is involved; the default model is `qwen2.5-coder`.
- If the server is not running or the model is not pulled, the error says
  which of the two it is. Tool calling needs a model that supports it.
- Ollama and Pollinations now share one OpenAI-compatible engine — the base
  URL is a *base* like in any OpenAI SDK, routes (`/chat/completions`,
  `/models`) are appended by dmsh.

### Proxy for every outbound request

LLM API, `websearch` and GGUF downloads all go through one setting:

| Mode | Behaviour |
|------|-----------|
| `auto` (default) | `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` / `NO_PROXY` from the environment, direct if unset |
| `off` | always direct, environment ignored |
| `custom` | `proxy_proto` + `proxy_host` + `proxy_port` + `proxy_user` + `proxy_password` |

- Protocols: `http`, `https`, `socks5`, `socks5h`; `no_proxy` takes hosts,
  `host:port`, `.suffix` and CIDR entries.
- One flag sets the whole address: `dmsh --proxy socks5://127.0.0.1:1080 "..."`,
  or field by field (`--proxy-mode`, `--proxy-proto`, `--proxy-host`,
  `--proxy-port`, `--proxy-user`, `--proxy-password`, `--no-proxy`,
  `--api-key`).
- **Settings screen**: `Ctrl+P` → *settings: proxy and endpoint* — one row
  per field plus a **connection test** that sends one real request and
  reports the route it took.
- The status line shows `proxy:on` / `proxy:off`, so the route is visible
  before the first connection error, not after. Credentials are never
  printed — only their source.

### Setup screen: change provider and model without restarting

`Ctrl+P` → *setup* edits provider (`auto` / `local` / `ollama` /
`pollinations`), remote model, local GGUF, endpoint and API key in one
window. The engine is rebuilt **first** and the config file is written only
after it loads — a failed switch keeps the engine that was already working.
Session-level model switches (below) stay session-only until **apply** here
writes them to `config.json`.

### Model menu with a live catalog

`Ctrl+O` (or the new `/models` command) opens the model menu. With a remote
provider it fetches that provider's live catalog from its open `/models`
route — no API key — sorted by id:

- type to filter (`qwen`, `coder`, `5.4`), `Backspace` edits the filter,
  `Esc` clears it, then closes the window;
- `Enter` switches the session to the chosen model and rebuilds the engine
  (session-only; **setup → apply** persists it);
- a failed fetch keeps its error on screen — an unreachable Ollama and a
  missing key look very different.

With the local provider the menu still lists .gguf files: install a
recommended model or switch the loaded one.

### TUI: three modes, a palette and a real terminal

- `Shift+Tab` cycles **ai → help → terminal**, `/mode` opens the list to
  pick from; the numeric `/1` `/2` `/3` shortcuts are gone.
- `Ctrl+P` opens the command palette: every command, mode, the setup and
  the settings screens, filter by typing. Long lists scroll with the
  selection. `F1` and `Ctrl+Q` work from any screen.
- **Terminal mode runs inside the app window**: a pty (`creack/pty` on
  unix, ConPTY on Windows) painted by a small screen emulator
  (`internal/vt`), so colours, resize and full-screen programs work while
  dmsh keeps its status line. `Shift+Tab` closes the shell and returns to
  the prompt.
- In help mode `run_command` is absent from the tool schemas entirely — a
  tool the model can see will be called.
- Background commands no longer freeze the TUI.

### Fixed

- **The model catalog never loaded.** `Ctrl+O` with a remote provider sat
  on "loading the model list…" forever: the fetch wrote its result into a
  channel that nothing read, and bubbletea only delivers what a command
  *returns*. The result is returned directly now, and a regression test
  drives the real fetch → `Update` path.
- **`/todo` looked empty.** The tool's result went only to the model, so
  the transcript showed a blank line and a bare `[tool] todo` marker. The
  first line of the result (`added [1] …`, `open [1] …`, or the error) is
  now printed under the marker, tasks are stored as a single line (a
  multi-line task used to inject blank rows), and the rendered status is
  no longer duplicated.
- **Provider/model selection unified.** One rule answers "which provider is
  live now" everywhere (`currentProvider`: session → its config → shell
  config → `auto`), one rule answers "is it remote" (`showsRemoteProvider`:
  `auto` with a local GGUF is local — same answer in `/model`, the status
  line and the model menu), and `/model` prints one shared text in both the
  TUI and the REPL. The setup screen deliberately still edits the *config*
  value, so `auto` does not silently turn into a concrete provider just by
  opening the window.
